# Алина Страховка — веб-приложение

Полноценный сайт подбора и оформления страховых полисов: калькулятор
цены по нескольким видам страхования со скидками, сравнение и сортировка
предложений «страховщиков», виджет обратного звонка, приём заявок
(включая незавершённые) и админ-панель с аккаунтами сотрудников.

Стек: Next.js (App Router) + TypeScript + Tailwind CSS + Prisma (SQLite).

## Быстрый старт

```bash
npm install
cp .env.example .env
npx prisma migrate dev
npm run dev
```

Приложение поднимется на http://localhost:3000. Первый заход на `/admin`
предложит создать аккаунт администратора — потребуется ключ
`ADMIN_BOOTSTRAP_KEY` из `.env`. После первого аккаунта ключ больше не
нужен, новых сотрудников добавляет уже залогиненный админ.

## Переменные окружения

См. `.env.example`. Обязательные — `DATABASE_URL`, `ADMIN_BOOTSTRAP_KEY`,
`ADMIN_SESSION_SECRET`. Остальные опциональны и по умолчанию просто
выключают соответствующую функцию:

- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — уведомление в Telegram о
  новой заявке/звонке. Не заданы — уведомления просто не отправляются.
- `NEXT_PUBLIC_YM_ID` / `NEXT_PUBLIC_GA_ID` — Яндекс.Метрика / Google
  Analytics. Не заданы — скрипты аналитики не подключаются вовсе (ни
  запроса, ни куки).
- `NEXT_PUBLIC_SITE_URL` — базовый URL для sitemap.xml, robots.txt,
  Open Graph и канонических ссылок.

## Архитектура интеграции со страховщиками

Партнёра-страховщика с реальным API пока нет, поэтому цены считает
"песочница" — но код уже разложен так, чтобы подключить реального
партнёра не переписывая остальное приложение:

- `src/lib/insurers/types.ts` — интерфейс `InsurerAdapter`. Всё, что
  считает цену полиса, реализует этот интерфейс: и текущие мок-страховщики,
  и будущий реальный партнёр.
- `src/lib/insurers/pricing.ts` — приблизительные формулы базовой цены
  по параметрам анкеты, включая скидки (безаварийный стаж, мультиполис) —
  не тарифная методика, а правдоподобная заглушка.
- `src/lib/insurers/adapters/mock.ts` — три мок-страховщика, которые
  берут базовую цену и применяют свой множитель/наценку.
- `src/lib/insurers/adapters/partner-template.ts` — **шаблон** реального
  адаптера (не используется приложением). Показывает, как должен
  выглядеть вызов API реального партнёра: запрос, маппинг ответа в общий
  тип `Quote`, обработка ошибок.
- `src/lib/insurers/registry.ts` — реестр адаптеров, которые реально
  участвуют в подборе цены. Чтобы подключить партнёра: скопировать
  `partner-template.ts`, реализовать вызов их API, добавить адаптер сюда.

Остальное приложение (калькулятор, API `/api/quote`, приём заявок,
админка) от источника цены не зависит — оно смотрит только на
`InsurerAdapter`.

## Данные и заявки

Заявки (лиды), незавершённые заявки (`PartialLead` — визитор начал
вводить контакты, но не отправил форму) и заявки на обратный звонок
(`CallbackRequest`) хранятся через Prisma (`prisma/schema.prisma`).
Все три видны в `/admin` на отдельных вкладках.

Формы (`/api/applications`, `/api/callback`) защищены honeypot-полем и
простым rate-limit по IP (`src/lib/rateLimit.ts`, in-memory — на
несколько инстансов сервера не масштабируется, для одного процесса
достаточно).

### Переход на Postgres

SQLite подходит для разработки и небольшого MVP, но плохо работает на
serverless/эфемерной файловой системе — на Vercel и подобных для
продакшена нужен Postgres:

1. Поднять Postgres — например, локально через `docker compose up -d`
   (см. `docker-compose.yml`), либо взять managed-инстанс (Railway,
   Neon, Supabase и т.п.).
2. В `prisma/schema.prisma` поменять `datasource db.provider` на
   `"postgresql"`.
3. Указать реальный `DATABASE_URL` в `.env` (формат
   `postgresql://user:password@host:5432/db`).
4. `npx prisma migrate deploy`.

Код приложения (`src/lib/db.ts`) от конкретной БД не зависит — кроме
специальной обработки относительного пути SQLite-файла, которая
срабатывает только при `DATABASE_URL`, начинающемся с `file:`.

### Админка

`/admin` защищена аккаунтами (`AdminUser`, email+пароль, хеш через
`scrypt`), а не общим ключом — ключ (`ADMIN_BOOTSTRAP_KEY`) нужен только
чтобы создать самый первый аккаунт. Сессия — подписанная HMAC cookie без
таблицы сессий.

## Деплой

Это full-stack приложение с API-роутами и базой данных — **GitHub Pages
не подходит** (в отличие от статических файлов в корне репозитория:
`index.html`, `links.html`, `feed.xml` — тех, что уже используются для
RSS-ленты Дзен и хаба ссылок Instagram, их лучше не трогать).

Подходящие варианты хостинга: Vercel (нативно для Next.js), Railway,
Render — с внешней Postgres-базой вместо SQLite.

## Что дальше

- Подключить реального партнёра-страховщика или агрегатора через
  `adapters/partner-template.ts`.
- Перевести БД на Postgres перед продакшен-деплоем (см. выше).
- Настоящие отзывы клиентов вместо примеров в `src/lib/reviews.ts`.
- Email-уведомления о заявках (сейчас есть только Telegram) — нужен
  SMTP/email-провайдер.
