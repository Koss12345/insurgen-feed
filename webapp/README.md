# Алина Страховка — веб-приложение

Полноценный сайт подбора и оформления страховых полисов: калькулятор
цены по нескольким видам страхования, сравнение предложений
«страховщиков», отправка заявки (лида) и админ-панель для их обработки.

Стек: Next.js (App Router) + TypeScript + Tailwind CSS + Prisma (SQLite).

## Быстрый старт

```bash
npm install
cp .env.example .env   # задайте свой ADMIN_KEY
npx prisma migrate dev
npm run dev
```

Приложение поднимется на http://localhost:3000. Страница `/admin`
защищена ключом из `ADMIN_KEY` (см. `.env`).

## Архитектура интеграции со страховщиками

Партнёра-страховщика с реальным API пока нет, поэтому цены считает
"песочница" — но код уже разложен так, чтобы подключить реального
партнёра не переписывая остальное приложение:

- `src/lib/insurers/types.ts` — интерфейс `InsurerAdapter`. Всё, что
  считает цену полиса, реализует этот интерфейс: и текущие мок-страховщики,
  и будущий реальный партнёр.
- `src/lib/insurers/pricing.ts` — приблизительные формулы базовой цены
  по параметрам анкеты (не тарифная методика, а правдоподобная заглушка).
- `src/lib/insurers/adapters/mock.ts` — три мок-страховщика, которые
  берут базовую цену и применяют свой множитель/наценку.
- `src/lib/insurers/adapters/partner-template.ts` — **шаблон** реального
  адаптера (не используется приложением). Показывает, как должен
  выглядеть вызов API реального партнёра: запрос, маппинг ответа в общий
  тип `Quote`, обработка ошибок.
- `src/lib/insurers/registry.ts` — реестр адаптеров, которые реально
  участвуют в подборе цены. Чтобы подключить партнёра: скопировать
  `partner-template.ts`, реализовать вызов их API, добавить адаптер сюда.

Остальное приложение (калькулятор, API `/api/quote`, приём заявок,
админка) от источника цены не зависит — оно смотрит только на
`InsurerAdapter`.

## Данные и заявки

Заявки (лиды) хранятся в SQLite через Prisma (`prisma/schema.prisma`,
модель `Application`). Для продакшена стоит перейти на Postgres/MySQL —
достаточно поменять `provider` в `schema.prisma` и `DATABASE_URL`; код
приложения (`src/lib/db.ts`) от конкретной БД не зависит, кроме
специальной обработки относительного пути SQLite-файла.

Админка (`/admin`) читает и обновляет статус заявок напрямую через Prisma
(server component), защищена простым общим ключом (`ADMIN_KEY` в cookie).
Это MVP-уровень авторизации — для продакшена с несколькими сотрудниками
стоит завести полноценные аккаунты.

## Деплой

Это full-stack приложение с API-роутами и базой данных — **GitHub Pages
не подходит** (в отличие от статических файлов в корне репозитория:
`index.html`, `links.html`, `feed.xml` — тех, что уже используются для
RSS-ленты Дзен и хаба ссылок Instagram, их лучше не трогать).

Подходящие варианты хостинга: Vercel (нативно для Next.js), Railway,
Render — с внешней Postgres-базой вместо SQLite (файловая БД плохо
работает на serverless/эфемерной файловой системе).

## Что дальше

- Подключить реального партнёра-страховщика или агрегатора через
  `adapters/partner-template.ts`.
- Перевести БД на Postgres перед продакшен-деплоем.
- Усилить авторизацию админки (аккаунты вместо общего ключа).
- Добавить капчу/rate-limit на `/api/applications`, если начнётся спам.
